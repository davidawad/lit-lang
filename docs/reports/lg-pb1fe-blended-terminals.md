# Blended terminal inventory and proposed splits

## Operational definition

A **blended terminal** is a `terminal` whose incoming edges, as shown by rule text or node/edge notes, admit both a result favourable to the package's `self` party and a result adverse to that party, while retaining one terminal outcome/payoff. I treated explicit notes using “blended,” “movant,” “losing party,” or “either party,” and converging edges from different actors or branches of a chance node as evidence. Counts below are source-level candidates; a common terminal reached from a prior result is included when the note or graph confirms that the prior result is not carried forward.

`self` here means the package's declared protagonist, not necessarily the named appellant or appellee in a particular matter. Proposed splits are design recommendations only for packages outside FRCP; those packages are not modified in this bead.

## FRCP split feasibility and matter trace

No `.lit` or `.case` change is made in this attempt. FRCP 56(a) identifies the winner as the *movant*, but the current `sj-ruling` is a chance node whose sole “Granted in full” edge has no party identity; its terminal is a decision node by `plaintiff`. The package supports no scenario fact that identifies which side moved. Splitting that edge into plaintiff-win and defendant-win branches would require an invented probability for who moved or would silently misclassify cases where the other side moved. The generic trial verdict has the same loss of identity: its two chance branches merge at `final-judgment-entered`, then share post-trial motions and appeal. Separate terminals alone cannot preserve that identity through those procedures. The matter note says the defendant moved, but that prose is not a typed rule input. These are modeling contradictions with the requested party-relative split in the available graph, not a source/citation gap.

Thus the start-state value does not reach summary judgment or trial. With no safe source edit, the after value remains **−$16,655** and the explain trace is unchanged. The case-specific terminal value in the existing stakes is `loss: $0`; if a typed defendant-won terminal were introduced, that existing loss stake would apply. The plaintiff-won terminal would use the existing `win: $500,000` stake. No new/unvalued stake is needed for those two outcomes. No other expectation was re-recorded.
