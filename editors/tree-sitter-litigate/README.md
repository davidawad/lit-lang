# tree-sitter-litigate

tree-sitter grammar for litigate: `.lit` rule modules and `.case` matters
(`docs/litigate/SPEC.md` §2-§3). Editor modes (`editors/{emacs,helix,nvim}`)
and anything else that wants a fast, incremental, error-tolerant tree build
on it. The compiler's own hand-written parser (`crates/litigate-syntax`) is
the source of truth for syntax. When the two disagree, fix this grammar.

## One grammar, two entry rules

Both file kinds use one grammar. The root `source_file` holds exactly one
of:

- `lit_file`, which starts with `module` (SPEC §3.1)
- `case_file`, which starts with `case` (SPEC §3.2, items in fixed order)

The first keyword decides which, so no dialect switch or file-extension
lookup is needed. Both kinds share references, records, literals and
expressions (§3.3), and one set of queries covers both. `tree-sitter.json`
registers the `lit` and `case` file types.

## How the grammar maps SPEC

- **Contextual keywords** (§2). Every keyword is extracted from the
  `identifier` word token, so a word is a keyword only where the grammar
  expects one. `default`, `note`, `p` and the rest stay usable as names.
  Inside a node body, an item `Ident|_ String ->` is an edge (§3.4). The
  field keywords and the edge clause keywords `by` and `p` are also valid
  edge ids there, aliased back to `identifier`. The `p "x" -> y` case is
  resolved by GLR (`conflicts: [[$.edge_decl]]`) because only the token
  after the keyword tells a clause from a new edge.
- **Citations** (§2). `cite` is followed by its text as a `string` (or a
  cite hole), then optionally `historical`. There is no citation lexing
  mode, so commas, braces, `§§` and URLs need no escape hatch and the
  grammar has no external scanner.
- **Expressions** (§3.3). Each precedence level is its own hidden rule,
  and every infix form surfaces as `binary_expression` with `left`,
  `operator` and `right` fields. Comparison is non-associative
  (`a < b < c` is an error). `match` may only head a whole expression.
- **Version requirements** (`^1.2.0`, §3.2) are one `version_req` token, so
  trivia inside one is an error.
- **Lexical parity.** What the compiler rejects lexically is rejected here
  too: whitespace is exactly space, tab, CR and LF (a no-break space is an
  `ERROR`, L0003), `_` groups digits only between two digits (`1__0` is no
  number, L0005), and a date must exist (`2025-02-30` is an
  `invalid_date` node in an expression, an `ERROR` elsewhere, L0004).
  Unknown typed-literal suffixes (`1.eur`) are errors in both. Semantic
  rules are compiler diagnostics only.

## Layout

| Path | What |
|---|---|
| `grammar.js` | root: word, extras, conflicts, `source_file` |
| `grammar/lit.js`, `grammar/case.js`, `grammar/values.js` | `.lit` rules, `.case` rules, shared value/expression/token rules |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `tree-sitter generate` and committed per tree-sitter convention |
| `queries/highlights.scm`, `locals.scm`, `folds.scm`, `indents.scm`, `injections.scm` | editor queries (`injections.scm` is intentionally empty: doc comments and citations are prose) |
| `test/corpus/*.txt` | one corpus file per construct family, plus `errors.txt` for inputs that must not parse |
| `test/highlight/` | highlight assertions for a `.lit` and a `.case` sample |
| `bindings/rust/` | the `tree-sitter-litigate` crate (`LANGUAGE`, the query sources) |
| `tests/conformance.rs` | Rust conformance test (below) |

## Commands

```bash
just tree-sitter-generate  # regenerate src/ from grammar.js and grammar/*.js
just tree-sitter-test      # regenerate (must match committed src/), tree-sitter test, script/merge-test
cargo nextest run -p tree-sitter-litigate   # bindings + conformance (part of the workspace gate)
```

The recipes use `tree-sitter` from `PATH` when it is the pinned version
(0.27.1, also in `package.json`). Otherwise they use `npx`. After editing
`grammar.js` or `grammar/*.js`, run `just tree-sitter-generate` and commit
`src/` with the change. `just ci` and CI fail when the committed parser is
stale.

## Merging grammar changes

`src/` stays committed: the crate's `build.rs` compiles `src/parser.c`, so
`cargo build` needs no node, and editor packages that build a grammar from
its repository (nvim-treesitter, Helix) expect it there. Two branches that
change different grammar rules both rewrite `src/parser.c`, though, so a
text merge of it always conflicts. `.gitattributes` gives the generated
`src/parser.c`, `src/grammar.json` and `src/node-types.json` the
`tsgenerate` merge driver, which keeps ours when both sides changed them
(no node or cargo needed). The grammar sources merge as text; then:

```bash
just tree-sitter-merge-driver   # once per clone (just install and just lit-sync do it)
git rebase origin/main          # or git merge: no conflict in src/
just tree-sitter-generate       # regenerate src/ from the merged grammar, then commit it
```

`script/merge-test` (run by `just tree-sitter-test`) checks this: in a
scratch repository, two branches changing different grammar rules conflict
on `src/parser.c` without the driver, rebase and merge cleanly with it,
and regenerate into a parser with both changes.

## Conformance

`tests/conformance.rs` runs with the workspace tests. It checks four things:

1. Every `.lit`/`.case` file in the repository parses with zero `ERROR` or
   `MISSING` nodes. The walk skips `.git`, `target`, `node_modules` and
   `.worktrees`. A deliberately malformed fixture must use another
   extension.
2. The grammar's keyword set equals `litigate_syntax::SyntaxKind`'s
   contextual keywords.
3. The SPEC §12 worked examples get the expected roots.
4. Lexical rejection parity: invalid characters, dates and digit groups
   the compiler rejects are rejected here (a fixed table, and property
   tests that every date-shaped literal and digit group is accepted here
   exactly when the compiler accepts it).
5. Property tests cover juxtaposed items, citation text boundaries, kebab
   identifiers, and that parsing any input returns a tree.

When the compiler parser lands, a file it accepts and this grammar rejects
is a grammar bug.
